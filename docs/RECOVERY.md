# Recovery

FIRMSGeoTools recovery is designed around a **portable configuration bundle** plus an optional operational-data backup.

## Portable recovery bundle

Export:

Linux/macOS:

```bash
python3 scripts/recovery.py export --env .env.local
```

Windows:

```powershell
python scripts/recovery.py export --env .env.local
```

The generated JSON contains:

- release/schema version;
- project configuration;
- FIRMS source configuration;
- AOI GeoJSON;
- optional regions GeoJSON;
- non-secret operational policy state;
- inventory of secrets that must be re-entered.

It does **not** contain secret values.

## Restore configuration

On a clean checkout:

```bash
python3 scripts/recovery.py unpack backups/firmsgeotools-recovery-YYYYMMDDTHHMMSSZ.json --output-dir config
```

This recreates:

- `config/aoi.geojson`;
- `config/regions.geojson` when present;
- `config/monitoring.json`.

Then:

1. create a new Supabase project;
2. create `.env.local`;
3. enter your own FIRMS/Telegram/install secrets;
4. run the normal installer;
5. run strict validation after the first normal monitoring cycle.

## Optional operational-data backup

To preserve accumulated events/detections:

Linux/macOS:

```bash
bash scripts/backup.sh .env.local
```

Windows:

```powershell
.\scripts\backup.ps1 -EnvFile .env.local
```

This creates:

- portable recovery JSON;
- a data-only SQL dump.

The SQL dump is optional and is not required to rebuild a working monitoring system.

## Secrets

Secrets are intentionally never exported.

Re-enter:

- FIRMS_MAP_KEY;
- TELEGRAM_BOT_TOKEN;
- TELEGRAM_CHAT_ID;
- INSTALL_TOKEN;
- optional admin chat/webhook secret.

Vault cron/dashboard secrets are automatically regenerated by migrations.

## Disaster-recovery priority

If the original Supabase project is unavailable, restore in this order:

1. public repository at the desired release tag;
2. portable recovery bundle;
3. user-managed secrets;
4. fresh Supabase project;
5. installer;
6. strict validation;
7. optional historical-data restoration.

A working monitoring system should not depend on possessing a database dump.
